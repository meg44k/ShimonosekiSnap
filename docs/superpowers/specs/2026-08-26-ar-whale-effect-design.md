# AR クジラエフェクト 設計書

- 日付: 2026-08-26
- 対象プロジェクト: shimonoseki-snap (React + TypeScript + Vite)

## 背景 / 目的

角島大橋(`tunoshima.jpg`)を写した写真をモニターに表示し、それをアプリのカメラで撮影すると、橋の上をクジラが飛んで海に帰っていくARエフェクトが表示される機能を追加する。ユーザーはそのエフェクトが発生した瞬間を写真として保存できる。

## 要件

- カメラに写った`tunoshima.jpg`(角島大橋の写真)を画像として認識する
- 認識したら、橋の上をクジラが飛び越えて海に戻るアニメーションを表示する
- カメラやモニターが動いた場合でも、橋の遠近・角度に合わせてクジラの軌道が追従する(本格的な画像トラッキングAR)
- 検出中は自動でアニメーションをループ再生する
- クジラが飛んでいる瞬間を写真として保存できる(既存の撮影・保存フローを拡張)
- クジラの見た目は、まずは無料のCC0/フリー素材の3Dモデルを使う(将来的にユーザー自身がデザインしたモデルに差し替え予定)

## 技術選定

**MindAR.js + Three.js** を採用する。

画像ターゲットのリアルタイムトラッキングに特化したライブラリで、完全クライアントサイド(サーバー不要)で遠近感を含めた本格的な追従が可能。Three.jsとの連携用ヘルパー(`MindARThree`)が提供されており、この用途に対する定番の選択肢。

検討した他の選択肢:
- **AR.js (NFTトラッキング)**: 同種のライブラリだが、マーカー生成ツールがDocker/Java依存で扱いにくく、Three.js連携もMindARほど洗練されていないため見送り
- **自前でOpenCV.js + ホモグラフィ推定**: 自由度は高いが実装コストが非常に高く、インターン期間内のスコープとしてはリスクが大きいため見送り

## アーキテクチャ

### 依存関係の追加

- `mind-ar`(`MindARThree`)
- `three`

### 新規ファイル

| ファイル | 役割 |
| --- | --- |
| `public/targets/tunoshima.mind` | `tunoshima.jpg`をオフラインでコンパイルした画像ターゲットデータ(MindARのコンパイラで生成し、リポジトリにコミット。ビルド時の自動生成はしない) |
| `src/assets/models/whale.glb` | 無料CC0のクジラ3Dモデル(Poly Pizza等から調達) |
| `src/features/ar/ArCameraView.tsx` | `MindARThree`の初期化、カメラ映像+Three.jsシーンのマウントを担当するコンポーネント |
| `src/features/ar/whaleAnimation.ts` | クジラの飛行軌道・イージングロジック |
| `src/features/ar/captureComposite.ts` | video映像とThree.jsのWebGLキャンバスを1枚に合成して撮影するユーティリティ |

### 既存ファイルへの変更

- `src/App.tsx`: `state === 'camera'`画面で、現状の自前`getUserMedia` + `<video>`実装を`ArCameraView`に置き換える。撮影ボタンの処理を`captureComposite`経由に変更する。`idle`/`preview`のロジック(保存・撮り直し)は既存のまま流用する

## データフロー

1. ユーザーが「カメラを起動」を押す
2. `ArCameraView`がマウントされ、`MindARThree`がカメラ取得・video要素生成・トラッキングループの開始を行う(既存の自前`getUserMedia`は使わなくなる)
3. 毎フレーム`tunoshima.mind`とマッチングを行い、`targetFound`イベントでクジラの3Dグループを表示してアニメーションを開始し、`targetLost`イベントで非表示にする
4. クジラは`mindarThree.addAnchor(0)`で得られるアンカー配下のThree.jsグループとして配置する。アンカーはマーカー(橋の写真)の姿勢に追従するため、カメラが動いても橋に対する相対位置が正しく保たれる
5. 撮影ボタン押下時、`captureComposite`が現在のvideoフレームと`renderer.domElement`(Three.jsのWebGLキャンバス)を1枚のcanvasに合成し、`photoUrl`(dataURL)を生成する。以降の保存・撮り直しは既存ロジックをそのまま使う

## クジラのアニメーション仕様

- マーカー座標系(画像中心を原点とした実寸相対座標)で軌道を定義する
- 1サイクル: 橋の一端の海面付近から浮上 → アーチを描いて橋を飛び越える → 反対側の海に着水して消える
- `targetFound`が継続している間、一定の間隔を空けてループ再生する
- `requestAnimationFrame`による自前トゥイーンで実装する(放物線状の位置補間、進行方向を向く姿勢補間)。Three.jsの`AnimationMixer`等の外部アニメーションデータには依存しない

## テスト・動作確認方法

- 別モニターに`tunoshima.jpg`を表示し、開発環境(`npm run dev`または`docker compose up`)でスマートフォン実機またはPCカメラから認識テストを行う
- 認識精度・遠近追従・ループ再生・撮影時の合成結果を目視確認する

## リスク・既知の懸念事項

- モバイル実機でのトラッキング性能: WASM処理のため機種によっては動作が重くなる可能性がある
- `.mind`ファイルはオフラインで1回コンパイルしてコミットする運用とする(対象画像`tunoshima.jpg`自体を差し替える場合は再コンパイルが必要)
- クジラモデルは暫定的にフリー素材を使用するため、最終的な見た目はユーザー自身のモデルに差し替える前提とする

## スコープ外

- クジラ以外のエフェクトやマルチターゲット対応
- 動画としての保存(今回は静止画のみ)
- モデル差し替えのためのアップロードUI(将来の別タスク)
